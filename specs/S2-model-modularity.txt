1. PURPOSE
Allow compatible IQA, restoration, grade and lesion replacement through a flat
artifact filename and explicit JSON contract, then restart, without rebuilding C++.
Current production artifacts and native outputs are the regression baseline.
No weights, calibration, precision, thresholds or default routing were intentionally
changed. This is an implemented architecture record, not a proposed design.

ModelManager is about 210 lines of initialization plumbing, routing, mutex protection,
progress, timing and the UI result boundary. It contains no ONNX/Torch types,
model filenames, resolutions, precision, tuple indices or channel mapping.
Four typed unique_ptr interfaces own persistent adapters. Their shared private
RuntimeContext keeps the ONNX environment alive. No Python/server bridge, model
reload per eye or concurrent calls to shared sessions/modules were introduced.

5. COMPLETE VERSION 1 CONFIGURATION SCHEMA
Root: exactly version=1, checkpoints_directory, iqa, restoration, grading, lesion.
Unknown keys, wrong types and missing required fields fail. All four stages must
have enabled=true. Disabled stages are rejected, not silently removed.
Each stage requires enabled, adapter, model, input, output; grading/lesion require
cam; lesion additionally requires classes and postprocessing. Adapter selection
is explicit and stage-specific. Model must be an existing flat filename: no slash,
backslash, colon, absolute path, '.' or '..'.

Fixed input requires width/height integers 1..8192 with product <=16,000,000;
channels=3, layout=NCHW, color=RGB, resize=pillow_bilinear; dtype float32, float16
or bfloat16; normalization. Optional name selects an ONNX input. Torch inputs are
positional. Fixed stages reject dynamic_spatial, accepted_dtypes and range.
Normalization type is none, imagenet or mean_std. None cannot specify mean/std.
Other types require three finite mean/std values, strictly positive std, absolute
magnitude <=1e6. Both normalized variants use those explicit arrays; no hidden
calibration/normalization defaults are applied.

Restoration input requires dynamic_spatial=true, channels/layout/color as above,
resize=none, normalization={type:none}, range=[0,1], nonempty accepted_dtypes
containing supported floating types; fixed width/height/dtype are rejected.
Output requires same_dimensions_as_input=true, range=[0,1], optional name.
Actual ONNX boundary metadata chooses conversion. JSON does not alter internal
graph precision, weights or quantization.

IQA output: type logits/probabilities; activation softmax/none respectively;
classes exactly a permutation of Good,Usable,Reject; optional ONNX output name.
Grading output: type/activation as IQA; classes exactly strings '0'..'4' in raw
artifact order; contract tensor or scores_and_activations. Tuple indices
scores_index/activations_index are required, distinct integers 0 or 1. Tensor
rejects indices. cam.enabled is required; enabled CAM requires the tuple.
Lesion output: logits/sigmoid or probabilities/none, channels=4, and the same
explicit tensor/two-tensor tuple contract. cam.enabled_by_default is required;
cam.environment_override is a string, empty allowed. Enabled CAM or a nonempty
override requires the tuple contract.

Lesion classes require exactly MA,HE,EX,SE once each, in any array order. Each
requires code, unique channel 0..3, threshold [0,1], minimum_area >=0 and
merge_distance [0,64]. Entries are parsed into canonical order. Extra classes
are unsupported. Postprocessing requires reference_size (0,8192], connectivity=8,
minimum_mean_probability=.5, overlay_alpha=.45. The latter three are explicit
invariants of this postprocessor version, not alternative configurable algorithms.
The full committed production JSON is appended below.

7. QUALITY STAGE CONTRACT
IQualityModel::infer(QImage) returns QualityResult: Quality enum, label, confidence,
array<float,3> probabilities always Good/Usable/Reject. Adapter owns preprocessing,
dtype, session and class mapping. Metadata requires one RGB NCHW input and one
floating [1,3] output, compatible dimensions and dtype. Names are discovered from
the single runtime input/output unless explicitly configured; no multi-output
guessing occurs. Logits use the unchanged max-subtracted float softmax. Explicit
probabilities are used directly and checked finite/[0,1]/sum within 1e-4 of one.
Canonical argmax drives the route. IQA is called once per patient eye.

8. RESTORATION STAGE CONTRACT
IRestorationModel::infer(QImage) returns restored QImage and forward timing.
No resize or ImageNet normalization. Input/output support dynamic spatial size;
actual output must be [1,3,H,W] at original size. Symbolic metadata channel size
is permitted and the small startup probe checks actual output. Current FP32
boundary is preserved; other declared floating boundaries have explicit conversion.
FP32 output is clamped [0,1], nearbyint(value*255) as before. ModelManager saves
restored.png and passes this exact image to grade/CAM and lesions.

9. GRADING STAGE CONTRACT
IGradingModel::infer(image,directory) returns grade, confidence, canonical
array<float,5> probabilities, CAM path, warnings and stage timings. Torch forward
accepts one image; floating scores must be [1,5]. Output is explicitly a tensor
or exactly two tensors at configured indices. Tuple activation is floating NCHW,
batch one. Raw class ordering maps to grades 0..4. FP32 softmax is applied only
to logits; explicit probabilities are checked and used directly. Current precision,
autograd and CAM warning strings are preserved.

10. LESION STAGE / CANONICAL TYPES
ILesionModel::infer(image,directory,progress) owns runtime inference/optional CAM
and supplies canonical borrowed FP32 CPU planes to the postprocessor. Scores must
be [1,4,configured H,configured W]. Logits get FP32 sigmoid; explicit probabilities
are checked finite/[0,1] and used directly. Upsampling to original size remains
bilinear align_corners=false. Owner tensor lives until postprocessing returns.
SegmentationProbabilities holds width/height and four std::span<const float>.
LesionResult holds four LesionChannelResult values with canonical codes, full masks,
raw/display regions and mask/probability/CAM paths; combined paths, warnings/timing.
LesionRegion retains rank, bbox, integer center, centroid, original/model area,
mean/max probability and source IDs. ResultSerialization produces existing UI keys.
No runtime tensor is exposed in public interfaces.

11. LESION POSTPROCESSING
Pure CPU C++/Qt; no Torch/ONNX dependency in the postprocessor. Finite probabilities
>= configured threshold produce full masks. Eight-neighbor components retain
scan-order IDs. Minimum display area is
max(1,ceil(minimum_area*original_width*original_height/reference_size^2)).
Only retained components merge, using the original reference-coordinate distance
and anisotropic pixel scaling/union rules. Bboxes, centroids, areas and probabilities
retain the original arithmetic. Display groups require mean >=.5, sorted by area
descending, mean descending, ID ascending. Full masks/raw regions remain independent
of display filtering, merging or UI Top-K. Existing artifact basenames/heatmaps
remain. Overlay is nearbyint(.55*image+.45*color), with MA (255,45,45), HE
(255,126,34), EX (255,224,32), SE (35,210,255).

12. FACTORY / CONTRACT VALIDATION CACHE
ModelConfig validates adapter choice; ModelFactory creates private implementations
and RuntimeContext. ONNX sessions are created as a pair; lesion then grade modules
load in the original order. Options retain full graph optimization, two ORT threads,
CUDA device zero. Metadata checks names/counts/shapes/dtype. Torch schema and an
actual configured-dtype no-grad forward validate explicit outputs/spatial/classes.
Restoration receives a black 32x32 probe. --validate-models forces these probes
in a fresh native CLI process. IQA is checked through metadata, preserving once-per-
eye patient IQA. Validation samples contain no patient data.

Normal startup runs a short-lived sibling RetinaGram native CLI on cache misses,
before loading the parent's persistent sessions/modules. Probe warm-up stays out
of the patient process; the original stage order remains. This is initialization,
not an inference bridge or model reload per image. Helper errors/stderr/timeout
fail startup; ready is published only after all adapters load successfully.
Successful markers are under AppLocalDataLocation/model-contracts. SHA256 includes
artifact bytes, contract version v2, Torch version, stage, input size/dtype/dynamic
flags/accepted dtypes, tuple indices, probability type and CPU/CUDA kind. Failed
stage validation is never cached. Semantic class/channel JSON is parsed every time.
Unwritable cache repeats validation rather than failing a valid model. Private
helper arguments carry config/checkpoint/cache directories. The internal testing
override RETINAGRAM_INTERNAL_CONTRACT_CACHE selects an isolated cache. A sibling
native RetinaGram executable is required on cache misses.

13. CUDA / CPU ROUTING
Torch CUDA when available unless RETINAGRAM_FORCE_CPU is SET, preserving original
presence-based behavior (even set '0' forces CPU; unset to enable CUDA). ORT CUDA
also requires an available provider. On Ort CUDA construction failure, BOTH ONNX
sessions are reset/recreated on CPU. Torch can remain CUDA in that mixed fallback.
Forced CPU uses CPU for both runtimes with the same BF16 artifacts/input. This
is initialization fallback, not a new analysis retry. ModelManager mutex serializes
initialization and whole analyses. Good uses original -> grade/CAM -> lesions;
Usable uses original -> restoration/save -> grade/CAM -> lesions on restored;
Reject returns RECAPTURE_REQUIRED, grade -1, no downstream patient-stage call.

14. GRAD-CAM
Grade target uses configured raw index of the canonical predicted grade; weighted
activation gradients/ReLU normalization/resizing remain unchanged. Save name is
grade_gradcam.png. Optional lesion CAM uses each configured raw channel and the
original full-mask masked objective/nearest target resize. A different CAM mechanism
needs an adapter/export. Tuple validation checks activation shape/type, not every
model's gradient topology; unusable/detached activations cause existing CAM warnings.
Tensor-only grade requires CAM false; tensor-only lesion requires disabled CAM
and empty environment override. No activation or CAM is synthesized.

15. EXACT REPLACEMENT STEPS
1. Copy a compatible artifact directly into the application's checkpoints/.
2. Edit that stage's model filename and actual input/output/mapping contract in
   config/models.json. Example grading.model: grade_bf16_cam.pt -> my_new_grade.pt.
3. Run RetinaGram.exe --validate-models in its native DLL environment.
4. Restart. Existing-adapter compatible replacements require no C++ build.
IQA example: my_iqa.onnx, its input size/dtype/normalization and real output order.
Restoration: my_restoration.onnx with declared accepted floating boundary types,
dynamic same-size RGB contract. Grade: my_new_grade.pt with real grades 0..4 order.
Lesions: my_lesions.pt; map MA=2,HE=0,EX=3,SE=1 if that is its actual raw order.
UI remains canonical. Source users edit project files; packaged users edit package
config/checkpoints. Deployment copies committed configuration for a new package.
--model-info prints active config/artifacts/adapters/input/class/channel mapping.
RETINAGRAM_MODEL_CONFIG chooses another JSON. Empty/missing/invalid explicit
overrides fail. Checkpoints_directory is relative to the JSON, except explicit
native constructor test overrides. Default config search climbs five levels from
the executable, then checks working directory. Configuration loads once at startup.

17. WHAT CONFIG CAN CHANGE
Compatible filename; fixed size; supported input dtype; normalization arrays/none;
logits vs probabilities; tensor vs two-tensor tuple/indices; canonical class/channel
order; supported CAM settings; class thresholds/area/merge/reference settings.
Input dtype does not convert weights. Changing thresholds changes behavior and
was NOT done to production defaults in this task.

23. KNOWN LIMITATIONS
Only the four explicit image tasks/contracts are supported. Probability/tensor-only
alternatives are implemented but production comparison exercises current tuple/
logit artifacts; replacements need representative accuracy/CAM checks. CPU BF16
is slow. Initial validation can take seconds/tens of seconds and needs the native
sibling executable. Cache validates contracts, not clinical accuracy, every spatial
size or gradient topology. GPU Usable is not bitwise reproducible in the original
baseline. Four stages remain required; canonical UI classes/display invariants fixed.

verify native package and write specs after implementation/validation.
