ANALYSIS STRUCTURE AND BEHAVIOR
------------------------------
* One bordered, padded segmented container for the four Analysis tabs. The
  reusable segmented helper also handles Grade, attention mechanism, image,
  Detection and Annotation modes with exclusive green selected buttons.
* Grade: Original / Grad-CAM / Overlay and live opacity percentage.
* Probability: available lesion classes with readable names; Grad-CAM /
  Probability; Original / Heatmap or Grad-CAM / Overlay. Initial state is
  Probability, HE, Overlay, 50%. Uses the selected class's actual probability
  path. There is no aggregate-layer or bounding-box fallback. Grad-CAM displays
  availability/status from the existing run and never generates a missing CAM.
* Detection: Boxes / Coordinates, raw checkbox, class selector and Top-K.
  Raw mode uses raw_regions and bypasses class filtering and Top-K. Box/card
  selection shares original pixel coordinates; selecting a card switches to
  Detection and highlights the card and box. Coordinate cursor updates the
  readout without rebuilding the screen.
* Annotation: Original / Mask / Overlay, four class visibility checkboxes,
  opacity/percentage and MA red / HE orange / EX yellow / SE cyan legend.
  It colors existing thresholded binary masks; the displayed threshold is 0.5.
  No model threshold is reapplied or changed.
* The black rounded image stage is 4:3. Each image is centered with its original
  aspect ratio. Display downscaling is separate from original-coordinate data.
  Legends and explanatory source text appear under the stage.
* Diagnostic summary: source caption, DR grade and mapped grade label, numeric
  confidence and meter, readable lesion-name pills, full-width paired confirm
  and review actions, lightweight masks link and compare action/arrow.
* The primary lesion table was replaced by responsive cards, with 3 desktop,
  2 medium and 1 small-screen columns. Cards include the lesion icon/name,
  Not assessed badge, coordinates, source description, mean probability and
  meter. Area, maximum probability and component count remain available in
  tooltips. Region counts remain visible above the grid.

BATCH STRUCTURE AND BEHAVIOR
---------------------------
* Centered 1440px maximum shell; 32 / 24 / 16px horizontal padding at desktop /
  medium / small breakpoints, 32px top and 96px bottom. Manrope 36px title,
  subtitle, divider and conditional state badge.
* One rounded workflow container, three columns with full internal vertical
  dividers on desktop; stacked steps and horizontal dividers below 1024px.
  Each step has a 32px green number badge. Folder actions are compact.
* Initial review text says to choose a folder; Patient List is disabled until
  discovery. There is no permanent empty Detected Images panel.
* Discovery supports patient folders, root patient.json and flat filenames.
  It detects unreadable inputs, unknown eye assignments, metadata errors,
  name conflicts, duplicate candidates, paired/single eyes and empty identified
  patient folders. Review shows actual counts, acknowledgement and selections.
* The conditional Detected Patients section has the seven source columns,
  duplicate OS/OD candidate radio choices, issue/status presentation and actual
  per-eye stages. Rejected items/reasons and a collapsible inverse-surface
  discovery log appear when applicable.
* Create patient-wise folders follows pc-gpu: Windows-safe ID_Name group or
  numbered Patient_001_ID_Name group, with Left_OS / Right_OD subfolders.
  Selected candidates form the real processing plan. Unresolved entries block
  start unless Skip unresolved entries is enabled. CLI relative-folder output
  behavior is preserved.
* GPU capacity comes from cudaGetDevice/cudaGetDeviceProperties for the current
  device: real name, total VRAM, max(1,floor(0.006*VRAM_MB+41.66)), selected image
  count and oversize/unavailable state. No fake production capacity values.
* Batch Progress has allowed Pause / Resume / Cancel controls, actual stage
  events, progress and six metrics. Atomic control flags and a condition
  variable implement pause/cancel at image boundaries; cancellation wakes a
  paused worker. Existing per-image inference remains unchanged.
* Busy-state changes now rebuild Batch so Choose Folder is enabled when model
  loading finishes. This specific startup-to-ready interaction is tested.

LIMITS OF THIS PASS
-------------------
This is verified component/control/conditional-state fidelity for Analysis
and Batch, not a pixel-perfect equivalence claim for every application page.
Qt text wrapping, borders, icon rendering and native control sizing have small
differences from browser CSS. Confirm/Flag retain the pre-existing native
status-message behavior; this pass does not add source web review persistence.
Cloud Sync remains the existing disconnected local integration. Native tests
do not establish clinical validity or broaden the earlier model parity study.
